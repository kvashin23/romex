# Ромекс Девелопмент — прототип сайта (HTML/CSS/JS)

Статический кликабельный прототип всех страниц по ТЗ. Без сборки, без npm —
чистые `.html` + один `assets/styles.css` + один `assets/main.js`. Можно
открыть любой файл прямо в браузере (двойной клик), либо развернуть на Vercel.

## Что внутри

| Файл | Страница |
|---|---|
| `index.html` | Главная |
| `object.html` | Страница объекта (NEO-квартал, шаблон для всех ЖК) |
| `commercial.html` | Торговые помещения |
| `flats.html` | Квартиры (каталог/поиск) |
| `mortgage.html` | Ипотека |
| `promotions.html` | Акции |
| `buying.html` | Способы покупки |
| `about.html` | О компании + команда |
| `investors.html` | Инвесторам |
| `offices.html` | Офисы продаж |
| `news.html` / `news-post.html` | Новости: список / чтение |
| `partners.html` | Партнёрам (агентам) |
| `keys.html` | Выдача ключей (опциональный блок из ТЗ) |
| `contacts.html` | Контакты |
| `404.html` | Страница 404 |

| `assets/main.js` | Слайдер, аккордеоны, табы, бургер-меню, формы, карусели |

## Отклонения от ТЗ (важно прочитать)

Мне разрешили отходить от ТЗ там, где это оправдано — вот что я поменял и почему:

1. **Один шаблон на объект.** В ТЗ подразумевается страница объекта — я сделал
   один гибкий шаблон `object.html` с полным набором блоков (видео/фото-хиро,
   поиск на 6 планировок, генплан с литерами, ход строительства, О компании).
   В реальной разработке под него заводится один компонент в CMS, а NEO-квартал
   и ЖК в Новороссийске — это просто два разных набора данных в нём же. Делать
   вторую физическую HTML-копию не имело смысла для прототипа.
2. **Страницы без детального ТЗ.** Для «Квартиры», «Ипотека», «Офисы продаж»,
   «Акции», «Инвесторам» в вашем ТЗ нет отдельных разделов с требованиями к
   структуре — только упоминания в шапке сайта. Я спроектировал их сам, по
   аналогии с блоками, которые уже описаны на главной и на странице объекта
   (тот же поиск, те же карточки), чтобы не рвать логику интерфейса и не
   оставлять в шапке нерабочие ссылки. Это моя гипотеза — стоит согласовать
   состав блоков отдельно.
3. **Генплан «с наведением на литер».** В ТЗ — интерактивная шахматка с
   наведением. Сейчас это плитки-литеры + список со свободными квартирами
   (клик разворачивает). Полноценный hover-генплан с реальными координатами
   корпусов появится только после интеграции с шахматкой Битрикса — раньше
   этого делать интерактив на реальных данных нет смысла.
4. **Выдача ключей.** Показал только клиентский сценарий (выбор объекта →
   дата → подтверждение). Админскую часть (добавление объектов/дат) и
   интеграцию с Битриксом не прототипировал — это бэкенд/CMS-функциональность,
   не интерфейс.
5. **Фото и рендеры — плейсхолдеры.** Везде, где должны быть реальные фото
   объектов, стоят текстурные заглушки с подписью (`рендер`, `фото к новости`
   и т.д.) — это то место, где нужны ваши материалы.
6. **Форма ипотечного калькулятора** — статический макет полей (как на
   текущем сайте), без реальной логики расчёта.

## Как открыть локально

Просто откройте `index.html` в браузере — сайт полностью статический,
сервер не нужен. Для проверки роутинга между страницами удобнее поднять
локальный сервер:

```bash
npx serve .
# или
python3 -m http.server 8000
```

## Как развернуть на Vercel через свой GitHub

### 1. Загрузите проект в GitHub

```bash
cd romex-site
git init
git add .
git commit -m "Прототип сайта Ромекс Девелопмент"
git branch -M main
git remote add origin https://github.com/<ваш-логин>/<название-репозитория>.git
git push -u origin main
```
Если удобнее — просто загрузите папку через веб-интерфейс GitHub
(«Add file → Upload files»), Git из терминала не обязателен.

### 2. Подключите репозиторий к Vercel

1. Зайдите на **vercel.com** → New Project.
2. Выберите **Import Git Repository** и авторизуйте доступ к вашему GitHub,
   если ещё не подключали.
3. Выберите репозиторий с этим проектом.
4. На экране настроек:
   - **Framework Preset** — выберите `Other` (это статический сайт, сборка не нужна).
   - **Build Command** — оставьте пустым.
   - **Output Directory** — оставьте пустым (или `.`), Vercel отдаст файлы как есть.
5. Нажмите **Deploy**.

Через 20–30 секунд Vercel выдаст рабочую ссылку вида
`https://<название-проекта>.vercel.app` — на ней будет открываться `index.html`,
а `404.html` автоматически подхватится Vercel как страница для несуществующих
адресов (это стандартное поведение для статических проектов).

### 3. Дальнейшие обновления

Любой `git push` в ветку `main` (или загрузка новых файлов через веб-интерфейс
GitHub) автоматически пересоберёт и обновит сайт на Vercel — отдельно
нажимать «Deploy» не нужно.

### 4. Свой домен (опционально)

В настройках проекта на Vercel — вкладка **Domains** → добавьте `romexdev.ru`
(или тестовый поддомен) и пропишите указанные Vercel DNS-записи у вашего
регистратора домена.
